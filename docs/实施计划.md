## 1. 总体策略

### 1.1 三条原则

1. **垂直切片，不按技术层横切。** 每个阶段结束都必须"能跑、能演示、能验收"，而不是"采集写完了但没有任何入口"。
2. **风险前置。** 最不确定的四件事（GDI 采集正确性、遮罩抢焦点、中文 IME、GDI+ 性能）在 P0 用 4 个 Spike 先验证掉，避免做到 P3 才发现要换方案。
3. **接口早冻结、功能晚膨胀。** `Frame` / `CaptureBackend` / `Document` 三个核心接口在对应阶段结束时冻结；新功能一律进 P6 backlog。

### 1.2 阶段划分逻辑

```
P0 基建+Spike        —— 先证明"能做"
   ↓
P1 采集+输出（CLI）   —— 打通像素闭环，无 UI 也能验收
   ↓
P2 遮罩+框选         —— 达成 MVP（热键→框选→复制/保存）
   ↓
P3 标注引擎          —— 达成 V1 核心价值（可编辑截图）
   ↓
P4 系统集成          —— 从"工具"变成"常驻软件"
   ↓
P5 兼容性+Beta       —— 从"我能用"到"大多数人能用"
   ↓
P6 V2（可选）        —— 边界能力与差异化
```

### 1.3 阶段门禁（Gate）

每个阶段结束必须回答四个问题，全部为"是"才进入下一阶段：

- [ ] 交付物齐全，代码在 `main` 上可构建、可运行？
- [ ] 验收清单全部通过（有记录，不是"感觉可以"）？
- [ ] 没有已知 P0/P1 缺陷被带进下一阶段？
- [ ] 技术方案/ADR 已同步本次做出的取舍？

## 2. 阶段总览

| 阶段 | 目的（一句话） | 估时 | 关键交付物 | 门禁 |
|---|---|---|---|---|
| **P0** 基建 + Spike | 证明技术路线可行，建立可 CI 的骨架 | 0.5–1 人日 | 工程骨架、4 份 Spike 结论 | 4 个 Spike 有明确结论 |
| **P1** 采集 + 输出 | 打通"像素从哪来、到哪去"的闭环 | 1–1.5 人日 | `--capture/--region/--selftest` | 区域截图与全屏裁剪逐像素一致 |
| **P2** 遮罩 + 框选 | 达成 MVP：热键→框选→复制/保存 | 2–2.5 人日 | 可交互遮罩 | 4K 下热键到可框选 < 300ms |
| **P3** 标注引擎 | 达成 V1 核心：可编辑截图 | 4–5 人日 | 8 种标注 + 工具栏 + 撤销 | 预览与导出逐像素一致 |
| **P4** 系统集成 | 变成可常驻的桌面软件 | 2 人日 | 托盘/配置/单实例/自启 | 双击即用、无控制台 |

| **P6** V2（可选） | 边界能力与差异化 | 10–20 人日 | WGC/滚动截图/OCR 等 | 单项验收 |

## 3. 风险与阶段的对应关系

| 风险（来自技术方案 §8） | 在哪个阶段被验证/收敛 | 处理方式 |
|---|---|---|
| GDI 采集黑屏/偏色（R1） | **P0 的 S1**、P5 | P0 先确认目标机器可用；P5 补提示与降级 |
| 混合 DPI/负坐标错位（R5/R6） | **P0 的 S1**、P1、P2 | P1 用"区域截图 == 全屏裁剪"自动化验证 |
| 遮罩抢焦点失败（R7） | **P0 的 S2**、P2 | 失败则 `AttachThreadInput`；再失败评估低层钩子 |
| 中文 IME（R3 相关） | **P0 的 S3**、P3 | EDIT 子窗口方案先做最小验证 |
| GDI+ 性能不足（R3 相关） | **P0 的 S4**、P3 | 超预算则评估 D2D/tiny-skia（D2） |
| 热键冲突（R8） | P2、P4 | 可配置 + 错误提示 |
| 剪贴板被占用（R10） | P1 | 重试 + 提示 |
| 大内存/泄漏（R12） | P1、P5 | soak 测试与句柄计数 |
| 杀软误报（R11） | P5 | 避免低层钩子、代码签名 |
| WGC 黄框（R2） | P6（若引入） | 仅作为可选后端并提示 |

> 原则：能在 1 天内验证掉的风险，不要拖到实现后期。

## 4. 各阶段详细计划

### P0：基建 + Spike（0.5–1 人日）

**目的**：建立可构建、可 CI、可运行的骨架；用 4 个时间盒（每个 ≤ 2 小时）的 Spike 回答"技术路线是否成立"。

#### 任务

| # | 任务 | 产出 |
|---|---|---|
| 0.1 | 初始化 Cargo 工程：`windows 0.62`（技术方案 §6.7 的 feature 子集）+ `image` | `Cargo.toml` |
| 0.2 | `build.rs` + `winresource`：嵌入 `PerMonitorV2` manifest、图标、版本信息 | `build.rs`、`assets/app.ico` |
| 0.3 | 模块骨架：`app/ capture/ ui/ annotate/ output/ platform/ util/` | 空模块 + `mod` 声明 |
| 0.4 | 错误类型（`thiserror`）、日志（文件 + stderr）、`--verbose` | `util/error.rs`、`util/log.rs` |
| 0.5 | CLI 骨架：`--help` / `--version` / `--capture` / `--selftest`（占位） | `app/cli.rs`、`main.rs` |
| 0.6 | CI：`fmt --check`、`clippy -D warnings`、`test`、`build` | `.github/workflows/ci.yml` |

#### Spike（每个写一页结论到 `docs/spikes.md`）

| # | 问题 | 通过标准 | 失败后的备选 |
|---|---|---|---|
| S1 | GDI `BitBlt` 在本机（含多屏/125%/RDP）能否截到正确画面？ | 尺寸正确、非黑像素占比 > 5%、DPI 正确 | 记录现象；评估 WGC 提前引入 |
| S2 | `RegisterHotKey` + 全屏 popup 能否稳定抢到焦点、Esc 关闭？ | 10/10 次成功，Esc 100% 生效 | `AttachThreadInput`；低层键盘钩子 |
| S3 | `EDIT` 子窗口 + 微软拼音能否正常输入中文并提交？ | 中英文混排、候选词、回车提交都正常 | 评估 egui 路线的成本（方案 B） |
| S4 | 4K DIB 上 GDI+ 画 8 个形状 + 重绘 10 次耗时？ | 单次重绘 < 16ms（估算可接受） | 评估 Direct2D / tiny-skia |

#### 验收

- [ ] `cargo run -- --selftest` 能运行并输出环境信息（屏幕尺寸、DPI、后端）
- [ ] `docs/spikes.md` 有 4 份结论，每份包含"通过/失败 + 证据 + 决策"
- [ ] CI 绿
- [ ] release 构建产物能启动，无缺失 DLL

#### 明确不做

遮罩交互、标注、托盘、配置、安装包。

### P1：采集与输出（1–1.5 人日）

**目的**：打通"像素从哪来 → 怎么裁剪 → 到剪贴板/文件"的闭环。此时**没有任何 UI**，全部通过 CLI 验证——这能让采集与输出先独立稳定下来。

#### 任务

| # | 任务 | 说明 |
|---|---|---|
| 1.1 | `Frame { width, height, stride, bgra, origin, backend }` | 自顶向下 BGRA |
| 1.2 | `Dib` RAII | `CreateDIBSection` + 内存 DC，Drop 时还原/删除 |
| 1.3 | `CaptureBackend` trait + `GdiBackend` | `capture(region)`，`SRCCOPY \| CAPTUREBLT` |
| 1.4 | 坐标与裁剪 | 虚拟桌面原点、负坐标、边界 clamp |
| 1.5 | 剪贴板 `CF_DIB` | 40 字节头 + 自底向上 + alpha=255；`OpenClipboard` 重试 |
| 1.6 | PNG 保存 | 工作线程编码、原子写、`Pictures\Screenshots`、Unicode 路径 |
| 1.7 | CLI：`--capture`、`--region x,y,w,h`、`--output`、`--clipboard` | 可脚本化 |
| 1.8 | `--selftest` 完整版 | 截图 → 全屏裁剪 vs 区域截图 → 剪贴板回读 → 保存 → 指标 |
| 1.9 | soak：连续 100 次采集 | 统计 GDI/USER 对象数、内存 |

#### 交付物

- `src/capture/{mod,gdi}.rs`、`src/output/{clipboard,files}.rs`、`src/platform/dib.rs`
- 可执行命令：
  ```powershell
  window-cap --capture --output out.png
  window-cap --region 100,100,800,600 --clipboard
  window-cap --selftest
  ```

#### 验收标准（必须逐条记录结果）

- [ ] 全屏截图尺寸 == `SM_CXVIRTUALSCREEN × SM_CYVIRTUALSCREEN`
- [ ] **区域截图 == 全屏截图同区域裁剪（逐像素）**，覆盖：正坐标、负坐标、跨屏、1px 边界；在静止画面下比较，若有时钟/动画干扰，允许 < 0.1% 像素差异
- [ ] 125% / 150% / 200% 缩放下上述一致性仍成立
- [ ] 剪贴板内容可粘贴到 画图、Word、微信（手工验证各一次）
- [ ] 连续 100 次：GDI 对象数波动 ≤ 2，内存回到基线
- [ ] 保存路径含中文用户名正常
- [ ] `--selftest` 失败时退出码为 1，可被 CI 判断

#### 明确不做

遮罩、热键、标注、托盘。

#### 风险与应对

| 风险 | 应对 |
|---|---|
| 目标机器 GDI 黑屏 | 记录到 `docs/known-issues.md`，P5 统一处理；P1 不因此阻塞 |
| 剪贴板被其他程序占用 | 3 次重试（10ms 间隔），失败返回可读错误 |
| 大图内存峰值 | 复用 DIB；避免同时持有两份 4K 帧 |

### P2：遮罩与框选（2–2.5 人日）

**目的**：达成 **MVP**——按热键冻结屏幕、拖拽框选、松手即复制并保存。这是用户第一次能"像用截图工具一样"使用它。

#### 任务

| # | 任务 | 说明 |
|---|---|---|
| 2.1 | 热键隐藏窗口 + `RegisterHotKey` | 默认 `Ctrl+Alt+A`；冲突提示（1409） |
| 2.2 | 遮罩窗口 | `WS_POPUP \| WS_EX_TOPMOST \| WS_EX_TOOLWINDOW`，覆盖虚拟桌面 |
| 2.3 | 显示时序 | 禁 DWM 动画、`SetForegroundWindow`/`AttachThreadInput`、恢复前台 |
| 2.4 | 冻结帧绘制 + 压暗 | 预压暗位图或 `AlphaBlend`；`WM_ERASEBKGND` 返回 1 |
| 2.5 | 选区状态机 | 拖拽创建、8 手柄、移动、方向键微调、`Shift` 缩放 |
| 2.6 | 尺寸标签与光标 | `宽 × 高`；`IDC_CROSS` / 方向光标 |
| 2.7 | 取消路径 | `Esc`、右键、点击不拖拽；释放资源、恢复前台 |
| 2.8 | 模态消息循环 | 防重入（热键在遮罩打开时忽略） |
| 2.9 | 端到端埋点 | 热键→首帧、拖拽帧率、输出耗时 |
| 2.10 | 复用 P1 输出 | 松手 → 裁剪 → 剪贴板 + 保存 |

#### 交付物

- `src/ui/{overlay,selection,cursor}.rs`、`src/app/hotkey.rs`
- 可演示：按热键 → 拖拽 → 粘贴

#### 验收标准

- [ ] 4K 下热键 → 遮罩可交互 < 300ms（记录实测）
- [ ] 拖拽重绘 ≥ 30fps（4K，全量重绘基线）；引入脏区重绘后 ≥ 55fps（P2 内完成优化）
- [ ] 多屏（含副屏在左/上）+ 混合 DPI 下，选区像素坐标精确
- [ ] `Esc` / 右键 / 单击 三种取消都正确，且原前台窗口恢复
- [ ] 遮罩打开时再按热键不会叠加第二个遮罩
- [ ] 连续 50 次截图无 GDI/USER 句柄泄漏
- [ ] 全屏游戏（无边框窗口模式）下可呼出遮罩并接收键盘

#### 明确不做

标注、工具栏、托盘、配置。

#### 决策点 D1

如果目标机器上出现无法解决的多屏/DPI 偏移，或 GDI 在主要场景失败率 > 10%：暂停 P3，评估提前引入 WGC 或"每屏一个遮罩窗口"。

### P3：标注引擎（4–5 人日）

**目的**：把"截图"升级为"可编辑截图"，达成 V1 的核心价值。本阶段是整个项目工作量最大、也最影响口碑的部分。

#### 任务

| # | 任务 | 说明 |
|---|---|---|
| 3.1 | `Document` + `surface` | 选区大小 DIB；`new/commit/rebuild/export`（技术方案 §7.3.5） |
| 3.2 | GDI+ 初始化与 RAII | `GdiplusStartup`、`GdipCreateFromHDC` 包装、`UnitPixel`、AA、flush |
| 3.3 | 形状渲染 | 箭头、直线、矩形、椭圆、画笔、高亮 |
| 3.4 | 文字 | EDIT 子窗口 + 子类化 + 提交/取消 + IME |
| 3.5 | 马赛克/模糊 | 块平均；`GdipFlush` 后直接改像素 |
| 3.6 | 序号标记 | 实心圆 + 白字，自动递增 |
| 3.7 | 工具栏 | 布局、命中、悬停、图标（Segoe Fluent Icons）、颜色/粗细 |
| 3.8 | 撤销/重做 | 命令栈 + 从底图重放 |
| 3.9 | 导出分发 | CF_DIB / PNG；导出与预览同源 |
| 3.10 | WYSIWYG 校验 | dump `surface` vs `export()` 逐像素比对 |
| 3.11 | 黄金图测试 | 固定 DIB 渲染 8 种形状，与 golden 图比对 |

#### 交付物

- `src/annotate/{mod,render,history,mosaic}.rs`、`src/ui/{toolbar,text_editor}.rs`
- 可演示：选区 → 画箭头/写中文/打马赛克 → 复制/保存

#### 验收标准

- [ ] 8 种标注全部可用，中文输入法正常（含候选词、回车提交）
- [ ] **预览与导出逐像素一致**（自动化脚本）
- [ ] 撤销/重做 20 步正确；撤销后无残留
- [ ] 4K 全屏导出（不含 PNG 编码）< 50ms
- [ ] 单次形状提交重绘 < 5ms
- [ ] 工具栏在 100% / 150% 缩放下可点击、不被屏幕边缘裁掉
- [ ] 文字框提交后，文字位置与输入框位置一致（±1px）

#### 明确不做

形状选中/二次编辑、贴图窗口、历史记录、OCR。

#### 决策点 D2

如果 P3 实测"提交一次形状"或"全屏重绘"明显超过预算（> 16ms/帧），启动一次 2 小时的 D2D/tiny-skia 评估，再决定是否替换渲染后端（接口不变）。

### P4：系统集成（2 人日）

**目的**：从"命令行工具"变成"可以常驻、开机自启、有托盘"的桌面软件。

#### 任务

| # | 任务 | 说明 |
|---|---|---|
| 4.1 | 托盘 | `Shell_NotifyIconW` + 菜单 + 气泡通知 |
| 4.2 | 单实例 | 命名互斥 + `FindWindow` + 激活已有实例 |
| 4.3 | 配置 | TOML schema、默认值、坏文件备份、托盘"重新加载" |
| 4.4 | 开机自启 | `HKCU\...\Run`，可开可关 |
| 4.5 | 延迟截图 | 定时器，3s/5s 可选 |
| 4.6 | 上次选区 | 记录 + 回放（可选） |
| 4.7 | 无控制台 | `windows_subsystem = "windows"`；错误用气泡/对话框 |
| 4.8 | CLI 与单实例转发 | `window-cap --capture` 发到已有实例 |

#### 交付物

- `src/app/{tray,config,single_instance}.rs`、`src/output/pin.rs`（可选）
- 可演示：双击 exe → 托盘常驻 → 热键/菜单/退出

#### 验收标准

- [ ] 双击 exe 无控制台，托盘出现，右键菜单可用
- [ ] 第二次启动只激活已有实例，不产生第二个托盘图标
- [ ] 修改配置里的热键 → 重新加载 → 生效
- [ ] 配置写坏 → 程序不崩溃，备份并回退默认值
- [ ] 自启开/关可逆，注册表无残留
- [ ] 退出时托盘图标消失、热键注销

#### 明确不做

设置 GUI、自动更新、多语言切换 UI、贴图增强。

### P5：兼容性硬化与 Beta（3–4 人日）

**目的**：把"我机器上能用"变成"大多数机器能用"，达到可发布质量。

#### 任务

| # | 任务 | 说明 |
|---|---|---|
| 5.1 | 测试矩阵执行 | Win10/11、DPI 四档、单/双/三屏、竖屏、RDP、HDR、游戏 |
| 5.2 | 异常路径 | 无权限、剪贴板占用、磁盘满、保存失败、热键冲突 |
| 5.3 | 性能调优 | 脏区重绘、启动预热、内存峰值 |
| 5.4 | soak | 连续 200 次截图；24h 常驻 |
| 5.5 | 崩溃与日志 | panic hook、日志轮转、可定位的上下文 |
| 5.6 | 打包与签名 | release 配置、manifest、图标、版本号、代码签名（可选） |
| 5.7 | 文档 | README、FAQ、已知问题清单 |
| 5.8 | Beta 发布 | 小范围试用 + 收集反馈 |

#### 验收标准

- [ ] 测试矩阵通过率 ≥ 95%，无 P0/P1 缺陷
- [ ] 4K 常驻内存 < 150MB；连续 200 次截图无句柄/内存增长
- [ ] 冷启动 < 300ms；热键到可框选 < 300ms（4K）
- [ ] 黑屏/DRM 场景有明确、可操作的提示
- [ ] 崩溃日志能复现定位（含版本/OS/DPI/后端）

## 7. 验收脚本

把下面这些命令固化进 `scripts/`，每个阶段跑一遍：

```powershell
# 环境与采集自检（P0/P1）
cargo run --release -- --selftest --verbose

# 全屏保存（P1）
cargo run --release -- --capture --output target/full.png

# 区域 + 剪贴板（P1）
cargo run --release -- --region 100,100,800,600 --clipboard --output target/region.png

# 坐标一致性（P1，自动化）
cargo test --test coordinate_consistency

# 句柄/内存 soak（P1/P5）
cargo run --release -- --soak 100

# 预览/导出逐像素一致（P3）
cargo run --release -- --verify-render

# 配置往返（P4）
cargo test --test config_roundtrip
```

建议的集成测试（`tests/`）：

| 测试 | 覆盖 |
|---|---|
| `coordinate_consistency` | 区域截图 == 全屏裁剪，含负坐标/跨屏 |
| `dib_encoding` | CF_DIB 头字段、行序、alpha |
| `render_golden` | 8 种形状与 golden 图比对 |
| `render_wysiwyg` | surface vs export 逐像素 |
| `config_roundtrip` | 默认值/坏文件/热键解析 |
| `geometry` | 手柄命中、选区归一化、边界 clamp |

## 8. 变更管理

| 情况 | 处理 |
|---|---|
| 阶段内想加新功能 | 记入 `docs/backlog.md`，不插队 |
| 核心接口要改（`Frame`/`Document`/`CaptureBackend`） | 写 ADR，标注影响范围，当阶段内完成迁移 |
| 发现方案不可行（如 GDI 在目标机不可用） | 触发对应决策点（D0/D1/D2），评估备选后再继续 |
| 用户反馈的 bug | 优先于新功能；P0/P1 缺陷当阶段修 |
| 性能不达标 | 先测量再优化；优化前记录基线 |
