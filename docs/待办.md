## 需求池

> 新需求先记录在这里，标注来源与大致优先级，评估后再挪到上面的待办列表。

- [ ] **截长图（滚动截图）** —— 待评估（2026-10-25 提出）
  - 目标：固定选区，捕获超出屏幕的长页面/长文档并拼接为一张 PNG
  - **已确认范围（2026-10-25）**：仅手动滚动；仅纵向拼接；最大高度做成配置项（`-1` = 不限）；不做自动滚动/横向
  - 交互草案：
    1. 选区确认后进入长图模式，隐藏遮罩并抓第一帧
    2. 屏幕角落显示悬浮控制条（`WS_EX_NOACTIVATE`，点击不抢目标窗口焦点）：`继续抓帧 / 完成 / 取消`，显示已抓帧数
    3. 用户用鼠标滚轮/滚动条滚动目标窗口后点“继续抓帧”，隐藏控制条→抓帧→自动拼接→重新显示
    4. 完成后复制到剪贴板，并按现有配置保存 PNG
    - 讨论结论：**不使用空格/Enter 等键盘快捷键**（会与页面按键冲突），改用控制条按钮
  - 拼接算法：新帧与上一帧做灰度 SAD/NCC，在纵向搜索重叠；要求唯一最优且误差低于阈值，无重叠时提示重新抓取；拼接后限制最大高度（配置）
  - 固定 header/footer：**待确认策略**
    - 方案 1（MVP）：接受可能重复，检测到连续帧顶部/底部高度相似时提示“可能包含重复页头/页脚”
    - 方案 2（V1）：比较连续帧的顶部/底部条带，若几乎一致则判定为固定条，拼接时跳过后续帧中的这部分（启发式，可能误判）
  - 关键风险：固定 header/footer 重影、动态内容/懒加载、无重叠匹配失败、超长图内存与 PNG 编码上限
  - 初步估算：手动拼接 MVP 约 2–3 天；固定条检测 +1 天；进度/撤销/完成提示 UI 约 1 天
  - 验收草案：浏览器长页面 ≥3 屏拼接无明显错位；固定页头场景给出提示或去重；失败可回退普通截图
