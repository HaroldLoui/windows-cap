## 需求池

> 新需求先记录在这里，标注来源与大致优先级，评估后再挪到上面的待办列表。

- [ ] **截长图（滚动截图）** —— 待评估（2026-10-25 提出）
  - 目标：固定选区，捕获超出屏幕的长页面/长文档并拼接为一张 PNG
  - 候选方案：
    - **A. 手动滚动 + 重叠匹配拼接（推荐先做 MVP）**：用户滚动一次，工具抓一帧；用上一帧底部与新帧顶部做灰度 SAD/NCC 匹配求纵向重叠，再拼接
    - **B. 自动滚轮 + 停止检测**：`SendInput` 固定像素滚动并连续抓帧；内容不再变化或无重叠时停止；适合浏览器/资源管理器，自定义滚动或无限加载需回退手动
    - **C. 应用 API / UI Automation / DOM 导出**：覆盖差、成本高，暂不考虑
  - 关键风险：固定 header/footer（sticky）导致重复、动态内容/懒加载、无重叠时匹配失败、超长图内存与 PNG 编码上限（建议限制最大高度 20000–30000px）
  - 初步估算：手动拼接 MVP 约 2–3 天；自动滚动 + 健壮性 +1–2 天；进度/撤销/完成提示 UI 约 1 天
  - 待确认：先做手动还是自动？只支持纵向还是也要横向？最大高度/是否允许降采样？
  - 验收草案：浏览器长页面 ≥3 屏拼接无明显错位；有固定 header 时给出提示；失败可回退普通截图
