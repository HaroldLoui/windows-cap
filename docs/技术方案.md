## 1. 结论摘要

### 1.1 可行性结论：可行，没有阻断性技术障碍

分三层看：

| 层次 | 结论 | 说明 |
|---|---|---|
| 能力层 | **完全具备** | Windows 同时提供 GDI、PrintWindow、DXGI Desktop Duplication、Windows.Graphics.Capture 四条采集路径，覆盖区域、全屏、窗口、独占全屏、HDR 等场景 |
| 绑定层 | **没有缺口** | `windows` crate 由 Windows 元数据（.winmd）自动生成，Win32 / COM / WinRT 全覆盖；本文涉及的所有 API 都已在本机 `windows 0.62.2` 中核对存在 |
| 产品层 | **主要成本在交互与兼容性** | 采集、剪贴板、保存本身是几百行的事；真正的工程量在遮罩交互、标注编辑器、多屏混合 DPI、各种黑屏兼容 |

一句话：**能做，且 `windows-rs` 是合适底座；但这是一个"采集 20%、交互 80%"的项目。**

### 1.2 推荐技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 语言 | Rust 2024 | 已确认本机 rustc 1.96 |
| 平台绑定 | `windows = "0.62"`，按功能开启 feature | 只开用到的 feature，控制编译时间与体积 |
| 区域/全屏采集 | **GDI `BitBlt` + 32bpp DIB** | 默认路径，无 GPU 依赖、RDP 可用 |
| 窗口采集 | `PrintWindow`（`PW_RENDERFULLCONTENT`） | windows-rs 把它放在 `Win32_Storage_Xps`，见 4.2 |
| 采集兜底（可选） | Windows.Graphics.Capture | 仅对独占全屏/游戏/HDR 场景启用，见 4.4 |
| 遮罩窗口 | **原生 Win32 `WS_POPUP` 窗口 + GDI 自绘** | 冻结帧 + 压暗 + 亮区 Blit |
| 标注渲染 | **GDI+**（抗锯齿矢量 + 文本） | 备选 tiny-skia / Direct2D，见 5.2、7.3 |
| 文本输入 | Win32 `EDIT` 子窗口 | 直接获得系统 IME，避免手写输入法 |
| 剪贴板 | windows-rs 直写 `CF_DIB`（+ 注册格式 `"PNG"`） | 约 150 行，见 7.4 |
| 编码/保存 | `image` crate（png/jpeg） | 工作线程执行 |
| 配置 | `serde` + `toml` | 见 7.5 |
| 托盘 | `Shell_NotifyIconW` | 原生实现，约 150 行 |
| 资源/清单 | `winresource`（build.rs） | 嵌 manifest、图标、版本信息 |

### 1.3 关键量化预估

> 以下为基于同类实现经验的**估算**，需在 M1/M2 阶段实测校准后固化到性能基线。

| 指标 | 目标值 | 说明 |
|---|---|---|
| 常驻冷启动 | < 150 ms | 托盘 + 热键窗口，按需创建遮罩 |
| 热键 → 遮罩可交互 | 80–250 ms（4K） | 含 BitBlt、窗口创建显示、首帧绘制 |
| 4K 全屏 BitBlt | 10–30 ms | 33 MB 内存拷贝，受内存带宽限制 |
| 选区拖拽重绘 | < 8 ms/帧 | 仅脏区域重绘时可稳定 |
| 4K PNG 编码 | 100–300 ms | 必须放工作线程 |
| 常驻内存 | 40–80 MB（4K） | 冻结帧 + 合成缓冲 |
| 单 exe 体积 | 3–6 MB | 原生 Win32 路线，静态 CRT |
| MVP（P0）工作量 | **4–5 人日** | 热键→选区→复制/保存 |
| V1（P0+P1）工作量 | **12–15 人日** | 含标注、托盘、配置、贴图 |

### 1.4 三条主要风险

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | **采集黑屏/偏色**：独占全屏 D3D、DRM/受保护窗口、部分硬件覆盖层、HDR 屏幕 | 用户偶发"截到全黑"，口碑致命 | GDI 为主 + WGC 可选兜底；明确提示；见 4.8 决策树 |
| R2 | **WGC 黄色边框**：未打包 exe 基本无法关闭，需要 MSIX + 受限能力 + 用户授权 | 每次截图屏幕闪黄框，体验不可接受 | **WGC 不作为默认路径**；只在兜底时启用并提示 |
| R3 | **交互细节**：混合 DPI、负坐标、焦点抢占失败、热键冲突、IME | 疑似"偶发"的错位/按键失效 | 坐标与焦点策略在架构期固化；测试矩阵覆盖 |

### 1.5 为什么不直接依赖现成截图库

`xcap`、`windows-capture` 能提供"帧"，但本项目的价值在帧之后：

- 它们不提供遮罩、选区、标注、贴图；
- 封装层会削弱对 DIB 生命周期、坐标原点、回退策略的控制；
- 每个额外依赖都带来版本耦合（例如 `windows` 主版本不一致时无法共存）。

结论：**采集与交互核心自研（约 1500–2500 行平台代码）**，实现时可参考它们的源码；仅在需要快速验证采集效果时临时使用。Ferrishot 就是一个佐证：它用 xcap 拿帧，但选区、标注、工具栏仍然全部用 iced 自己实现。

> 补充：`xcap` 0.9.x 在 docs.rs 上构建失败（截至调研时），选型时需自行验证其维护状态与 Windows 后端行为。

## 2. 目标、范围与约束

### 2.1 产品定位

常驻托盘、全局热键触发的 **截图 + 标注 + 贴图** 工具：

- 单 exe、免安装、无运行时依赖；
- 默认离线，不联网；
- 对标 Flameshot 的交互，但按 Windows 原生习惯（托盘、开机自启、混合 DPI）做。

### 2.2 V1 用户故事（P0/P1）

1. 按热键 → 屏幕冻结 → 拖拽框选 → 松手 → 自动复制到剪贴板，托盘气泡提示。
2. 选区后可用箭头/矩形/椭圆/画笔/文字/马赛克标注 → `Ctrl+C` 复制 / `Ctrl+S` 保存。
3. 选完区域可直接"贴"到屏幕上（置顶悬浮小窗），用于对照抄写。
4. 托盘菜单：截图、延迟截图、设置、开机自启、退出。
5. 热键可在配置文件中修改，冲突时给出可读提示。

### 2.3 非目标（V1 明确不做）

| 非目标 | 原因 |
|---|---|
| 跨平台（macOS/Linux） | 采集抽象层预留接口，但 V1 只做 Windows；避免为抽象付出成本 |
| 录屏/直播 | 与定位不同，技术栈（编码、音视频同步）差异大 |
| 云上传/图床 | 涉及网络、隐私、密钥管理 |
| 滚动截图 | 需要 UI Automation/滚动模拟 + 图像拼接，单独一个里程碑 |
| HDR 精确色彩 | 需要 WGC + 浮点格式 + tone mapping，V2 评估 |
| 无障碍支持 | V2 |

### 2.4 硬约束

| 约束 | 说明 |
|---|---|
| 系统版本 | Windows 10 1809+ / Windows 11 |
| 权限 | `asInvoker`，不要求管理员；**UAC 安全桌面、更高完整性级别窗口无法采集**（Windows 安全模型决定，非实现问题） |
| 分发 | 单 exe；MSVC CRT 静态链接；无需安装 |
| 依赖 | 不引入 Qt/WebView/大型运行时 |
| 安全 | 无网络请求；不上传截图；日志不含图像内容 |

## 4. 屏幕采集技术调研

### 4.0 前置条件：DPI 感知与坐标系

这是所有截图工具的第一道坑，必须在架构期确定：

| 项 | 做法 |
|---|---|
| 进程 DPI 感知 | `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)`，**必须在创建任何窗口之前**调用；同时在 exe 内嵌 manifest 声明 `PerMonitorV2`（两者一致） |
| 坐标单位 | 全链路使用**物理像素**，不做逻辑像素换算 |
| 虚拟桌面 | `GetSystemMetrics(SM_XVIRTUALSCREEN / SM_YVIRTUALSCREEN / SM_CXVIRTUALSCREEN / SM_CYVIRTUALSCREEN)`；原点可能为负（副屏在主屏左侧/上方） |
| 选区结果 | 直接是截屏图像坐标（客户端坐标 = 图像坐标） |
| 每窗口 DPI | `GetDpiForWindow`（用于 UI 缩放系数） |
| 多屏 DPI | `GetDpiForMonitor`（用于诊断/日志） |

**关键结论**：只要进程是 PMv2 且所有计算用物理像素，混合 DPI 下"截出来的图"永远是对的；错的只可能是自绘 UI 的尺寸。所以 UI 尺寸单独乘 `dpi/96` 即可，不要反过来缩放图像坐标。

### 4.1 GDI BitBlt（默认路径）

**原理**：从屏幕 DC 把合成后的桌面像素拷贝进 32bpp DIB。

```rust
// 示意，非最终代码
let screen = GetDC(None);
let mem = CreateCompatibleDC(Some(screen));
let mut bmi = BITMAPINFO::default();
bmi.bmiHeader.biSize = size_of::<BITMAPINFOHEADER>() as u32;
bmi.bmiHeader.biWidth = w;
bmi.bmiHeader.biHeight = -h;          // 负数 = 自顶向下，行序与内存一致
bmi.bmiHeader.biPlanes = 1;
bmi.bmiHeader.biBitCount = 32;
bmi.bmiHeader.biCompression = BI_RGB.0;
let hbm = CreateDIBSection(Some(mem), &bmi, DIB_RGB_COLORS, &mut bits, None, 0)?;
SelectObject(mem, HGDIOBJ(hbm.0));
BitBlt(mem, 0, 0, w, h, Some(screen), x, y, ROP_CODE(SRCCOPY.0 | CAPTUREBLT.0))?;
```

**优点**

- 无 GPU/D3D 依赖，RDP、虚拟机、老显卡都能用；
- 代码量小（约 100 行），启动即用；
- Windows 7 起可用，覆盖面最大；
- 采集的是 DWM 合成后的桌面，窗口化程序（含 Electron/WinUI）都能正确截到。

**限制**

| 限制 | 说明 | 缓解 |
|---|---|---|
| 独占全屏 D3D 黑屏 | 游戏切到独占全屏后，桌面合成器拿不到内容 | WGC/DDA 兜底，或提示用户切无边框窗口 |
| 硬件覆盖层 | 部分视频播放器、HDR 内容走 overlay，可能黑/偏色 | 同上 |
| 受保护内容 | 窗口设置 `WDA_EXCLUDEFROMCAPTURE`（Win10 2004+）或 DRM 视频会黑 | 无法绕过（这是安全设计），提示 |
| 光标 | BitBlt 不含鼠标指针 | `GetCursorInfo` + `DrawIconEx` 手动绘制（可选） |
| 无脏矩形 | 每次全量拷贝 | 截图是一次性的，可接受 |
| 内存带宽 | 4K 一次 33MB | 复用 DIB、避免重复创建 |

**性能**：主要受内存带宽限制，4K 约 10–30ms，1080p 约 3–8ms（估算，需实测）。

### 4.2 PrintWindow（窗口截图）

**用途**：只截某个窗口（含被其他窗口遮挡的情况），不依赖桌面合成结果。

**windows-rs 的坑**：`PrintWindow` 不在 `Win32::UI::WindowsAndMessaging`，而在 **`Win32::Storage::Xps::PrintWindow`**（feature `Win32_Storage_Xps`）。很多人找不到它。

```rust
PrintWindow(hwnd, hdc, PRINT_WINDOW_FLAGS(PW_RENDERFULLCONTENT))?;
```

- `PW_RENDERFULLCONTENT = 2`（Win8.1+）：让 DWM 渲染完整内容，能截到 UWP、Electron、WinUI、部分 D3D 窗口；
- 不传该标志时，很多现代窗口只会返回黑/白块。

**优点**

- 能截被遮挡的窗口；
- 不需要目标窗口可见（但最小化窗口没有渲染内容，仍拿不到）；
- 不依赖屏幕分辨率/多屏布局。

**限制**

| 限制 | 说明 |
|---|---|
| 部分 GPU 加速窗口返回黑 | 需要 WGC 回退 |
| 最小化窗口无效 | DWM 没有内容，拿不到帧 |
| 同步阻塞 | `PrintWindow` 是同步调用，可能阻塞较长时间，**不要放 UI 线程**；或放在带超时监控的工作线程 |
| 边界误差 | 用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 得到不含阴影的真实边界 |

**适用**：V1 的"截窗口"模式，优先 PrintWindow，失败回退 WGC（可选）。

### 4.3 DXGI Desktop Duplication（DDA）

**原理**：接管某个显示输出的帧流，`AcquireNextFrame` 拿到 GPU surface，再拷回 CPU。

**优点**

- 官方文档明确支持**独占全屏 DirectX 应用**的采集；
- 有 dirty rect / move rect，适合连续采集；
- 提供鼠标指针形状与位置（`GetFramePointerShape`）；
- 帧格式固定 `DXGI_FORMAT_B8G8R8A8_UNORM`。

**限制**

| 限制 | 说明 | 来源 |
|---|---|---|
| 每个输出一个 duplicator | 多程序/多实例可能互相占用失败 | DXGI 文档 |
| 混合显卡（Optimus）问题 | 对独显运行 DDA 会返回 `DXGI_ERROR_UNSUPPORTED` | 微软排障文档 |
| 会话切换/RDP | `DXGI_ERROR_ACCESS_LOST`、远程会话下常不可用 | 实践反馈 |
| 需要 D3D11 设备 | 代码量与 WGC 相当 | — |
| 旋转屏 | surface 是未旋转的，需要自己旋转 | DXGI 文档 |

**结论**：**不适合"单帧截图"**，是录屏/连续采集的方案。V2 若要录屏再引入。

### 4.4 Windows.Graphics.Capture（WGC）

**这是 Windows 上"最正确"的采集 API**，但对截图工具有一个致命约束（见下）。

**流程**

```
D3D11CreateDevice
  → CreateDirect3D11DeviceFromDXGIDevice（Win32_System_WinRT_Direct3D11）
  → IGraphicsCaptureItemInterop（Win32_System_WinRT_Graphics_Capture）
       CreateForMonitor(hmon) / CreateForWindow(hwnd)
  → Direct3D11CaptureFramePool::CreateFreeThreaded(device, B8G8R8A8_UNORM, 2, size)
  → pool.CreateCaptureSession(item)
  → session.SetIsCursorCaptureEnabled(false)
  → FrameArrived / TryGetNextFrame
  → ID3D11Texture2D → CopyResource 到 staging → Map → CPU 缓冲
```

**版本与能力**

| 能力 | 最低版本 |
|---|---|
| `GraphicsCaptureItem` / `FramePool` / `Session` | Windows 10 1803（17134） |
| `IGraphicsCaptureItemInterop::CreateForMonitor` | Windows 10 1903（18362） |
| `IsBorderRequired` | Windows 11 21H2 / Server 2022（20348、22000+） |
| 运行前检测 | `GraphicsCaptureSession::IsSupported()` |

**黄色边框（关键决策依据）**

WGC 默认在采集对象周围绘制黄色边框提示"正在被采集"。关闭它需要：

1. 应用在包清单里声明 `graphicsCaptureWithoutBorder` 受限能力；
2. 运行时调用 `GraphicsCaptureAccess::RequestAccessAsync(Borderless)`，由用户授权；
3. 再设置 `session.SetIsBorderRequired(false)`。

也就是说：**未打包（unpackaged）的普通 exe 没有包清单，基本无法关闭黄框**。对截图工具而言，每次按热键都让屏幕闪一下黄框是不可接受的，因此：

> **WGC 不作为默认采集路径**，只作为"独占全屏/游戏/HDR"的兜底；如果未来要默认启用，需要改用 MSIX 分发并申请受限能力。

**其他限制**

| 项 | 说明 |
|---|---|
| 最小化窗口 | 没有渲染内容，拿不到帧 |
| 首帧延迟 | 设备/池/会话初始化 100ms 量级，不适合"按下热键立刻冻结"的交互 |
| HDR | 需要 `R16G16B16A16_FLOAT` 全链路 + tone mapping，否则会过曝/裁剪 |
| 光标 | `IsCursorCaptureEnabled`，默认关闭 |
| 依赖 | D3D11 + WinRT + COM，代码量 400–600 行，编译体积增加 |
| 隐私/合规 | 系统会持续显示采集指示；不适合"偷偷截屏"（我们也不做） |

### 4.5 其他方案（评估后排除）

| 方案 | 结论 | 原因 |
|---|---|---|
| Magnification API | 排除 | 用于屏幕放大器，不是通用采集 |
| `DwmGetDxSharedSurface` | 排除 | 未公开 API，随版本变化，禁用 |
| `Windows.UI.Composition` 截帧 | 排除 | 无公开单帧接口 |
| Snipping Tool 的特权接口 | 排除 | 系统应用专用 |
| 第三方注入/挂钩 | 排除 | 违反安全模型，杀软误报 |

### 4.6 采集方案对比矩阵

评分 1–5（5 最好），"风险"列越少越好。

| 维度 | GDI BitBlt | PrintWindow | DXGI DDA | WGC |
|---|---|---|---|---|
| 系统版本覆盖 | 5（Win7+） | 5 | 4（Win8+） | 3（Win10 1803+） |
| 区域/全屏截图 | 5 | 1（仅窗口） | 4 | 4 |
| 窗口截图（被遮挡） | 1 | 4 | 1 | 5 |
| 独占全屏 | 1 | 1 | 5 | 5 |
| 最小化窗口 | 1 | 1 | 1 | 1 |
| HDR 正确性 | 2 | 2 | 3 | 5（需浮点格式） |
| 光标支持 | 2（手动绘制） | 2 | 5 | 5（开关） |
| 无边框干扰 | 5 | 5 | 5 | **1（黄框）** |
| RDP/虚拟机 | 5 | 4 | 2 | 3 |
| 首帧延迟 | 5 | 4 | 4 | 3 |
| 实现成本（越高越省） | 5 | 4 | 2 | 2 |
| 依赖体积 | 5 | 5 | 3 | 2 |

### 4.7 选型与分层策略

```
CaptureRequest
├─ Region / VirtualScreen ──→ GDI BitBlt
├─ Window ─────────────────→ PrintWindow → 失败 → WGC（可选 feature）
└─ Game / HDR（V2）─────────→ WGC（提示黄框）或 DDA（录屏）
```

代码上用 trait 隔离：

```rust
pub struct Frame {
    pub width: u32,
    pub height: u32,
    pub stride: u32,
    pub bgra: Vec<u8>,      // 自顶向下
    pub origin: (i32, i32), // 屏幕坐标原点
    pub backend: BackendKind,
}

pub trait CaptureBackend {
    fn name(&self) -> &'static str;
    fn capture(&mut self, source: CaptureSource) -> Result<Frame, CaptureError>;
}
```

`BackendKind` 写入日志，便于用户排障时反馈"用的是哪个后端"。

### 4.8 黑屏/偏色排查决策树

```
截图结果异常
├─ 全黑
│  ├─ 目标是独占全屏游戏？ ── 是 ──→ 提示改用无边框窗口，或启用 WGC 兜底
│  ├─ 目标窗口设置了 WDA_EXCLUDEFROMCAPTURE？ ── 是 ──→ 无法采集，明确提示
│  ├─ 正在 RDP/远程会话？ ── 是 ──→ 已知限制，建议本地操作
│  └─ 其他 ──→ 降低概率：检查 DPI 感知是否生效、是否截到了错误坐标
├─ 部分窗口黑
│  └─ 窗口模式改用 WGC；或 PrintWindow 的 PW_RENDERFULLCONTENT
├─ 颜色发灰/过曝
│  └─ HDR 屏幕：GDI 只能拿到 SDR 色调映射结果；V2 用 WGC 浮点格式
└─ 图像整体偏移
   └─ 进程不是 PMv2 / 用了逻辑坐标；检查 manifest 与 SetProcessDpiAwarenessContext
```

## 5. 交互层技术调研

### 5.1 交互需求拆解

遮罩层本质上是一个"全屏画布"应用，需要：

1. **窗口**：无边框、置顶、不显示在任务栏/Alt+Tab、跨多显示器、立即显示无动画；
2. **绘制**：冻结帧 + 压暗 + 选区亮区 + 边框/手柄 + 尺寸标签 + 工具栏；
3. **输入**：鼠标拖拽/悬停、键盘快捷键、中文 IME 文本输入、光标形状切换；
4. **刷新**：拖拽时高帧率，静止时零开销；
5. **DPI**：混合 DPI 下 UI 尺寸合理，图像坐标绝对准确。

### 5.2 候选方案对比

#### 方案 A：原生 Win32 + GDI/GDI+

| 维度 | 评价 |
|---|---|
| 窗口控制 | ★★★★★ 样式/置顶/焦点/无动画完全可控 |
| 绘制控制 | ★★★★★ 像素级；GDI Blit + GDI+ 抗锯齿 |
| IME/文本 | ★★★☆☆ 需借 `EDIT` 子窗口（见 7.3），但方案成熟 |
| 工具栏开发 | ★★☆☆☆ 全部自绘：命中测试、悬停、提示、图标 |
| 体积/启动 | ★★★★★ 3–6MB，启动 <150ms |
| 无 GPU 环境 | ★★★★★ RDP/虚拟机可用 |
| 跨平台 | ★☆☆☆☆ 无 |

#### 方案 B：egui / eframe

| 维度 | 评价 |
|---|---|
| 窗口控制 | ★★★★☆ `ViewportBuilder` 支持 `with_decorations(false)`、`with_always_on_top()`、`with_taskbar(false)`、`with_position()`、`with_mouse_passthrough()` |
| 绘制控制 | ★★★★☆ 立即模式，画什么很直观；纹理上传 4K 约几十 ms |
| IME/文本 | ★★★★★ 内置 `TextEdit`，中文输入开箱即用 |
| 工具栏开发 | ★★★★★ 按钮/滑条/颜色面板/悬停全现成 |
| 体积/启动 | ★★☆☆☆ 8–15MB，首次窗口/GPU 初始化 100–300ms |
| 无 GPU 环境 | ★★★☆☆ wgpu 有 WARP 回退，但 RDP 下体验需实测 |
| 跨平台 | ★★★★★ |

关键细节：egui 全屏窗口跨多显示器时，`pixels_per_point` 由窗口所在显示器决定，混合 DPI 下会整体缩放。做法是**强制 `pixels_per_point = 1.0`**，所有 UI 尺寸用物理像素自己算。

#### 方案 C：iced

`ferrishot`（现已改名 Peashot，Rust 写的 Flameshot 替代品）已经验证了这条路：技术栈是 **iced 0.14（wgpu + canvas） + xcap 0.7 + arboard 3**，支持 Windows/macOS/Linux。但 iced 的 retained 模型、canvas 文本编辑、窗口置顶/多屏定位都需要额外适配，学习和调试成本高于 egui；对本项目没有明显收益。

#### 方案 D：winit + softbuffer + tiny-skia

winit 负责窗口/输入/IME，softbuffer 把 CPU 像素缓冲呈现到窗口，tiny-skia 负责矢量绘制。兼顾"无 GPU"和"现代化输入处理"，但需要自己接文字排版（cosmic-text），工程量介于 A 与 B 之间。

#### 方案 E：Slint / Tauri

- Slint：声明式、效果不错，但许可模型（GPLv3 / 商业 / 署名）需要评估，且自绘画布能力不如直接上 GDI；
- Tauri：WebView 体积/启动/透明窗口/DWM 交互都更复杂，截图工具不需要 Web 技术栈。

**均不推荐。**

### 5.3 关键横切问题

| 问题 | 方案 A（原生） | 方案 B（egui） |
|---|---|---|
| 中文 IME | `EDIT` 子窗口承载输入，提交后 GDI+ 栅格化 | `TextEdit` 原生支持 |
| 混合 DPI | 物理像素 + UI 缩放系数 | 强制 `pixels_per_point = 1.0` |
| 抢焦点 | `SetForegroundWindow` + `AttachThreadInput` 兜底 | winit `focus_window` |
| 无动画显示 | `DWMWA_TRANSITIONS_FORCEDISABLED` | winit 窗口属性 |
| 工具栏 | 自绘 + 命中测试（约 500–800 行） | 现成控件 |
| 撤销/重做 | 命令栈（自己写，约 100 行） | 同样自己写 |

### 5.4 选型结论

**默认走方案 A（原生 Win32）**，理由：

1. 截图工具的核心是"冻结帧 + 像素级遮罩"，原生窗口最直接，不跟框架的 DPI/合成/事件模型打架；
2. 目标用户里有大量 RDP/虚拟机/低配环境，无 GPU 依赖是真实优势；
3. 体积与启动速度符合"常驻小工具"的定位；
4. 中文 IME 有成熟解法（EDIT 子窗口），不是阻塞项。

**如果团队更看重"两周内出完整标注 UI"**，选 B 也合理：核心采集/输出层不变，只把遮罩层换成 eframe；代价是 +5–10MB、GPU 依赖、需要处理 `pixels_per_point`。

切换成本评估：遮罩层重写约 **2–3 人日**，`capture`/`output`/`app` 三层完全复用。

## 6. 总体架构

### 6.1 分层

```
┌──────────────────────────── app ────────────────────────────┐
│ 生命周期、单实例、托盘、热键、配置、CLI、通知                 │
├──────────────┬──────────────────┬───────────────────────────┤
│   capture    │    annotate      │        output             │
│  GDI/WGC     │  形状模型/渲染    │  剪贴板/文件/贴图          │
├──────────────┴──────────────────┴───────────────────────────┤
│                 ui：遮罩窗口（Win32 + GDI/GDI+）              │
├─────────────────────────────────────────────────────────────┤
│        platform：Win32 的 RAII 封装（DIB/DC/字体/COM）        │
└─────────────────────────────────────────────────────────────┘
```

设计原则：

- `platform` 只做资源管理与 errno 转换，不含业务；
- `capture` / `annotate` / `output` 不依赖窗口，可单测；
- `ui` 是唯一知道"屏幕坐标、窗口句柄、消息循环"的层；
- `app` 负责状态机与生命周期，不直接调 Win32。

### 6.2 运行时结构

```
[主线程]
  message loop
    ├─ 热键隐藏窗口 ── WM_HOTKEY ──→ CaptureFlow
    ├─ 遮罩窗口 ────── 鼠标/键盘 ──→ UiState
    ├─ 托盘窗口 ────── 菜单/回调 ──→ AppAction
    └─ 贴图窗口 ────── 拖动/滚轮 ──→ PinWindow
[保存线程]
    └─ PNG 编码 + 写文件 ──→ 完成后 PostMessage 回主线程
[（可选）WGC 线程]
    └─ FrameArrived ──→ 拷贝到 CPU ──→ channel ──→ 主线程
```

### 6.3 线程模型

| 线程 | 职责 | 约束 |
|---|---|---|
| 主线程 | 所有窗口的创建/消息处理、GDI 采集、剪贴板 | Win32 窗口线程亲和，**禁止**在其他线程操作 |
| 保存线程 | PNG/JPEG 编码、落盘 | 通过 channel 接收 `Image`，完成后 `PostMessage` |
| WGC 线程（可选） | 帧池事件、GPU→CPU 拷贝 | 只处理 COM/D3D，不碰窗口 |

GDI 采集放主线程的原因：4K 也就 10–30ms，跨线程反而要搬 33MB 数据；只有编码值得异步。

### 6.4 状态机

```
                  hotkey / tray
        ┌────────────────────────────┐
        ▼                            │
     [Idle] ──capture──► [Capturing] ──ok──► [Selecting]
        ▲                                  │      │
        │                                  │      ├─ drag ──► [Selecting]
        │                                  │      ├─ esc ───► [Idle]
        │                                  │      └─ mouseup ─► [Annotating]
        │                                  │                     │
        │                                  │      copy/save ◄────┤
        │                                  │                     │
        └──────────── [Exporting] ◄────────┴─────────────────────┘
                          │
                          └─► [Pinned]（可选）
```

每个状态的进入/退出动作、可接受事件、禁止操作，都要在实现前列成表（见 7.2）。

### 6.5 数据模型

```rust
pub struct Point { pub x: i32, pub y: i32 }
pub struct RectI { pub x: i32, pub y: i32, pub w: i32, pub h: i32 }

/// 自顶向下 BGRA，行对齐 = width * 4
pub struct Bitmap {
    pub width: u32,
    pub height: u32,
    pub bgra: Vec<u8>,
}

pub struct Shot {
    pub frame: Frame,       // 冻结帧（整个虚拟桌面，含 DIB/DC，见 4.7）
    pub origin: (i32, i32), // 虚拟桌面左上角屏幕坐标
}

pub struct Document {
    pub selection: RectI,         // 选区在屏幕/图像中的位置
    pub surface: Dib,             // 成品表面：选区大小，底图 + 已提交标注（唯一真源）
    pub shapes: Vec<Shape>,       // 矢量模型，用于撤销/重做/重建
    pub undo: Vec<Command>,
    pub redo: Vec<Command>,
}

pub enum Shape {
    Line { a: Point, b: Point, style: Stroke },
    Arrow { a: Point, b: Point, style: Stroke },
    Rect { rect: RectI, style: Stroke },
    Ellipse { rect: RectI, style: Stroke },
    Pen { points: Vec<Point>, style: Stroke },
    Highlight { points: Vec<Point>, style: Stroke },
    Text { pos: Point, text: String, font: FontSpec, color: Color },
    Mosaic { rect: RectI, block: u32 },
    Blur { rect: RectI, radius: u32 },
    Step { center: Point, index: u32, style: Stroke },
}

pub struct Stroke {
    pub color: Color,     // RGBA
    pub width: f32,       // 物理像素
}
```

坐标约定：

- `Shape` 的坐标全部是 **document 本地像素**（相对选区左上角）；
- `surface` 按这个坐标系渲染，一块像素同时服务预览与导出（见 7.3.5）；
- 预览时整块 `BitBlt` 到屏幕的 `(selection.x, selection.y)`；
- 导出直接读 `surface`，不经过屏幕坐标。

> 说明：`windows 0.62` 的 WinRT 命名空间 feature 去掉了 `Windows_` 前缀（如 `Graphics_Capture`），与 0.5x 不同；Cargo 报错时以 `cargo add windows --features ...` 的提示为准。

## 7. 关键模块详设

### 7.1 采集层

#### 7.1.1 数据结构与生命周期

- `Frame` 持有 `Vec<u8>`，跨线程移动（`Send`），不可克隆（33MB）；
- 采集器内部复用 DIB（`Dib` 结构，Drop 时 `SelectObject` 还原、`DeleteObject`、`DeleteDC`）；
- 每次截图创建新 `Frame`，旧帧在遮罩关闭后释放；避免长期持有两个 4K 帧。

#### 7.1.2 GDI 实现要点

| 要点 | 说明 |
|---|---|
| DIB 必须 32bpp、负高度 | 否则行序颠倒，后续按行裁剪会错 |
| `CAPTUREBLT` | 带上分层窗口（菜单、提示框、DWM 阴影） |
| DC 释放 | `GetDC`→`ReleaseDC`，`CreateCompatibleDC`→`DeleteDC`，全部 RAII |
| 失败处理 | `BitBlt` 返回 `Result`；空指针检查；错误转 `windows::core::Error` |
| alpha 通道 | GDI 写出的是 0，导出 RGBA 时统一置 255 |
| 光标 | 需要时用 `GetCursorInfo` + `DrawIconEx` 画到 DIB 上 |

#### 7.1.3 多显示器

- 一次抓整个虚拟桌面，坐标原点 `(vx, vy)` 可能为负；
- 选区的屏幕坐标 = 客户端坐标 + 窗口原点；图像坐标 = 屏幕坐标 - 虚拟桌面原点；
- **单窗口覆盖整个虚拟桌面**即可，无需每屏一个窗口（见 7.2.5）；
- 显示器布局变化（插拔/改分辨率）时，下次截图重新计算，不做热重建。

#### 7.1.4 窗口模式

流程：

```
GetForegroundWindow? 或 光标下窗口（WindowFromPoint）
→ IsWindowVisible / IsIconic 过滤
→ DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS) 取真实边界
→ DwmGetWindowAttribute(DWMWA_CLOAKED) 过滤 UWP 幽灵窗口
→ PrintWindow(PW_RENDERFULLCONTENT)
→ 全黑？→ WGC 回退（若编译了 feature）
```

#### 7.1.5 黑帧检测（仅窗口模式）

- 统计非零像素比例；`< 0.1%` 视为"可能黑屏"；
- 只作为回退触发条件，不弹错误（纯黑窗口是合法内容）；
- 记录到日志：`backend=gdi source=window hwnd=0x... black_ratio=0.000`。

#### 7.1.6 WGC 接入（可选）

- 编译期 feature `wgc`，运行时 `GraphicsCaptureSession::IsSupported()` 检测；
- 只实现 `capture_window` / `capture_monitor` 的单帧路径：建池 → 等一帧 → 拷贝 → 关闭会话；
- 首次启用时提示"将出现系统黄色采集边框"；
- 失败时回退 GDI，不阻断主流程。

### 7.2 遮罩层与选区

#### 7.2.1 窗口参数

| 项 | 值 | 原因 |
|---|---|---|
| 类样式 | `CS_HREDRAW | CS_VREDRAW` | 尺寸变化重绘 |
| 窗口样式 | `WS_POPUP` | 无边框/标题栏 |
| 扩展样式 | `WS_EX_TOPMOST | WS_EX_TOOLWINDOW` | 置顶、不进 Alt+Tab/任务栏 |
| 位置 | 虚拟桌面矩形 | 覆盖所有显示器 |
| 背景 | 无画刷（`hbrBackground = null`），`WM_ERASEBKGND` 返回 1 | 避免闪白 |
| 光标 | 类光标 `IDC_CROSS` | 框选 |

#### 7.2.2 显示时序（避免闪烁/焦点失败）

```
1. 先采集（此时还没有任何窗口，不会截到自己）
2. CreateWindowExW（不带 WS_VISIBLE，或带但先 SetWindowPos 到目标位置）
3. DwmSetWindowAttribute(DWMWA_TRANSITIONS_FORCEDISABLED, TRUE)  // 禁用淡入
4. ShowWindow(SW_SHOW) + SetWindowPos(HWND_TOPMOST, ..., SWP_SHOWWINDOW)
5. SetForegroundWindow + SetFocus；失败则 AttachThreadInput 后重试
6. SetCursor(IDC_CROSS)
7. InvalidateRect + UpdateWindow
```

关闭时恢复原前台窗口（可选，提升体验）。

#### 7.2.3 绘制策略

每帧（`WM_PAINT`）：

```
BeginPaint
  BitBlt(dim 位图, 全屏)                                    // 背景压暗
  若存在选区：
    BitBlt(窗口 DC, sel.x, sel.y, sel.w, sel.h,
           doc.surface.dc, 0, 0, SRCCOPY)                   // 亮区 + 已提交标注
  绘制选区边框 + 8 个手柄 + 尺寸标签
  绘制拖拽中的临时形状（尚未提交，直接画在窗口 DC）
  绘制工具栏（若有选区）
EndPaint
```

关键：亮区不再单独维护"原图亮块"，而是直接贴 `Document::surface`——它同时包含底图和已提交的标注，预览与导出共用同一块像素（见 7.3.5）。

**压暗的两种实现**：

| 方案 | 内存 | 速度 | 结论 |
|---|---|---|---|
| 预生成暗化位图（每像素 ×0.45） | +33MB（4K） | 一次 BitBlt，最快 | 默认 |
| 1×1 黑色 DIB + `AlphaBlend` 拉伸 | 0 | 4 次小 AlphaBlend，稍慢 | 内存敏感时 |

> 与整屏"亮区还原位图"相比，`surface` 只有选区大小（最大一屏），反而更省内存。

#### 7.2.4 脏区域重绘

- 拖拽选区时，`InvalidateRect` 只传"旧选区 ∪ 新选区"的外接矩形；
- 工具栏悬停只重绘工具栏矩形；
- `WM_PAINT` 用 `GetUpdateRect` 限制 Blit 范围；
- 目标：4K 下拖拽稳定 60fps（<8ms/帧）。

#### 7.2.5 混合 DPI 与多屏

- 一个窗口覆盖虚拟桌面，所有绘制用物理像素；
- `GetDpiForWindow(hwnd)` 取窗口所在显示器的 DPI，得到 `ui_scale = dpi / 96.0`，只用于工具栏/标签尺寸；
- 不处理 `WM_DPICHANGED`（窗口不移动）；若要支持运行中改分辨率，重新截图即可；
- 备选：每屏一个窗口（更符合 DWM 语义，但状态同步复杂，V1 不用）。

#### 7.2.6 选区交互

- 手柄：4 角 + 4 边，命中容差 6px；光标按方向切换（`IDC_SIZENWSE` 等）；
- 选区内拖拽 = 移动；`Ctrl` 拖拽 = 复制？V2；
- 方向键微调；`Shift` 缩放；`Ctrl+Shift` 对称缩放（Flameshot 语义）；
- 单击不拖拽 = 取消（避免误触产生 1px 选区）；
- 尺寸标签：`宽 × 高`，选区上方/下方自动避让；字号随 `ui_scale`。

#### 7.2.7 取消与恢复

- `Esc`/右键/失去焦点（可配置，且文本编辑子窗口获得焦点不算失焦）→ 销毁窗口、释放位图、恢复原前台窗口；
- 取消不写剪贴板、不落盘；
- 释放后 `SetProcessWorkingSetSize` 不做（交给系统）。

### 7.3 标注引擎

#### 7.3.1 渲染后端对比

| 后端 | 质量 | 速度 | 依赖 | 文本 | 结论 |
|---|---|---|---|---|---|
| GDI | 无抗锯齿 | 最快 | 系统 | `DrawTextW`，CJK 可用 | 只做 UI 文本 |
| **GDI+** | 抗锯齿、渐变 | 中 | 系统 | `GdipDrawString`，CJK 好 | **默认** |
| Direct2D + DirectWrite | 最好 | 快 | D3D/DXGI | 最好 | V2 可选 |
| tiny-skia | 好 | 快 | 纯 Rust | 需 cosmic-text | 想要可测试/可移植时 |

**选 GDI+ 的理由**：系统自带、零额外依赖、抗锯齿够用、文本对中文友好；4K 全屏重绘一次标注层约 5–15ms（估算），可接受。

> windows-rs 已提供 `Win32_Graphics_GdiPlus`（`GdiplusStartup`、`GdipCreateFromHDC`、`GdipSetSmoothingMode`、`GdipDrawString` 等）。需要在主线程 `GdiplusStartup` 一次，退出时 `GdiplusShutdown`。

#### 7.3.2 形状与绘制细节

| 形状 | 要点 |
|---|---|
| 箭头 | 主线 + 两条斜线；线宽 > 4px 时箭头比例随之放大 |
| 矩形/椭圆 | `GdipDrawRectangle` / `GdipDrawEllipse`；`Shift` 等比 |
| 画笔 | 采样点抽稀（距离 < 2px 丢弃），`GdipDrawLines` 连成折线 |
| 高亮 | 半透明宽笔刷，`CompositingMode = SourceOver` |
| 文字 | 见 7.3.3；提交后转成 `Shape::Text`，绘制时用字体句柄缓存 |
| 马赛克 | 按 `block` 分块求平均色后填充；`block` 默认 12px，随滚轮调整 |
| 模糊 | 盒式模糊 2–3 次近似高斯；V1 可只做马赛克 |
| 序号 | 实心圆 + 白字，自动递增；位置可拖动（V2） |

#### 7.3.3 文字输入（中文 IME 方案）

```
用户点击文字工具 → 在点击处创建 EDIT 子窗口
  ├─ 样式：WS_CHILD | WS_VISIBLE | ES_MULTILINE | ES_AUTOVSCROLL | ES_WANTRETURN
  ├─ 字体：Microsoft YaHei UI（随 ui_scale）
  ├─ 颜色：文字色 = 当前颜色；背景 = 半透明深色（EDIT 不支持透明，画一个底板）
  ├─ 子类化：拦截 VK_RETURN（提交）/ VK_ESCAPE（取消）/ VK_TAB
  └─ IME：系统自动为该 EDIT 启用输入法候选窗
提交 → GetWindowTextW → 生成 Shape::Text → DestroyWindow → Invalidate
```

要点：

- `EDIT` 的 `WM_CHAR` 由系统处理，中文、拼音候选、手写都正常；
- 不需要自己处理 `WM_IME_*`；
- 文本栅格化用 GDI+，字体与 EDIT 中一致，所见即所得；
- 多行：`Shift+Enter` 换行，`Enter` 提交。

#### 7.3.4 撤销/重做

```rust
enum Command {
    Add(Shape),
    Remove { index: usize, shape: Shape },
    Modify { index: usize, before: Shape, after: Shape },
    Clear(Vec<Shape>),
}
```

- `undo` / `redo` 两个 `Vec<Command>`；
- 每次提交形状入栈，清空 `redo`；
- 撤销 = 弹出最后一个命令 → `Document::rebuild` 从底图重放剩余形状（见 7.3.5）；
- `Ctrl+Z` / `Ctrl+Shift+Z`；
- 上限 100 步，避免内存膨胀。

#### 7.3.5 成品表面（surface）：预览与导出的唯一真源

**核心原则**：标注不是"画在屏幕上再截一次"，而是矢量模型被光栅化到一块**选区大小的 DIB**；预览把它贴到屏幕上，导出直接读它的像素。

```
                   ┌───────── 矢量模型 Vec<Shape> ─────────┐
                   │  提交 / 撤销时重放                     │
                   ▼                                       │
 frame ──crop──► [ Document::surface (w×h, 32bpp DIB) ] ──┴──► 读像素 ──► CF_DIB / PNG
                   │
                   └── BitBlt 到遮罩窗口 = 预览（所见即所得）
```

**三块内存，职责分明**：

| 缓冲 | 尺寸 | 内容 | 生命周期 |
|---|---|---|---|
| `frame` | 虚拟桌面 | 冻结帧（同时是压暗的源） | 遮罩打开期间 |
| `Document::surface` | 选区 | 底图 + 已提交标注 = **成品** | 选区确定 → 导出完成 |
| 拖拽中的临时形状 | — | 未提交的预览，只画在窗口 DC | 一次拖拽 |

> 工具栏、手柄、尺寸标签、`EDIT` 输入框都不在这三块里，只画在窗口 DC 上，所以导出天然不会带上——不需要任何"隐藏 UI"的技巧。

**生命周期**：

1. **创建**：选区确定时 `CreateDIBSection(w_sel, h_sel)`，从 `frame` 按 `(sel.x, sel.y)` BitBlt 过来；
2. **提交形状**：只重绘形状包围盒（外扩线宽 + AA 余量），把形状 push 进 `shapes`；
3. **撤销/重做/改选区**：从 `frame` 重新 BitBlt 底图，再按顺序重放 `shapes`；
4. **导出**：直接读 `surface` 的像素，不再渲染。

```rust
pub struct Document {
    pub selection: RectI,   // 屏幕坐标
    pub surface: Surface,   // 选区大小，成品像素
    pub shapes: Vec<Shape>,
    pub undo: Vec<Command>,
    pub redo: Vec<Command>,
}

impl Document {
    pub fn new(frame: &Frame, sel: RectI) -> Result<Self> {
        let mut surface = Surface::new(sel.w as u32, sel.h as u32)?;
        BitBlt(surface.dc, 0, 0, sel.w, sel.h, Some(frame.dc), sel.x, sel.y, SRCCOPY)?;
        Ok(Self { selection: sel, surface, shapes: vec![], undo: vec![], redo: vec![] })
    }

    /// 提交一个标注：只重绘包围盒，立刻反映到预览和导出
    pub fn commit(&mut self, shape: Shape) -> Result<()> {
        let bbox = shape.bounds().inflate(shape.stroke_width() + 4.0);
        let g = GdiPlus::from_hdc(self.surface.dc)?;   // RAII：GdipCreateFromHDC
        g.set_page_unit_pixel();                        // ★ 见 7.3.6
        g.set_antialias();
        g.set_clip(bbox);
        render_shape(g.raw(), &shape);                  // 预览/导出共用同一函数
        g.flush();                                      // ★ 像素操作前必须
        self.shapes.push(shape);
        Ok(())
    }

    /// 撤销/重做/选区变化：从底图重放
    pub fn rebuild(&mut self, frame: &Frame, sel: RectI) -> Result<()> {
        BitBlt(self.surface.dc, 0, 0, sel.w, sel.h, Some(frame.dc), sel.x, sel.y, SRCCOPY)?;
        let g = GdiPlus::from_hdc(self.surface.dc)?;
        g.set_page_unit_pixel();
        g.set_antialias();
        for shape in &self.shapes { render_shape(g.raw(), shape); }
        g.flush();
        self.selection = sel;
        Ok(())
    }
}

/// 导出：不重绘，直接拿 surface 的像素
pub fn export(doc: &Document) -> Image {
    Image::from_bgra(doc.surface.width, doc.surface.height, doc.surface.pixels())
}
```

**导出分发**：

| 目标 | 处理 |
|---|---|
| 剪贴板 `CF_DIB` | 追加 40 字节 `BITMAPINFOHEADER`（`biHeight` 为正），逐行倒序拷贝，alpha=255 |
| 剪贴板 `"PNG"` | BGRA→RGBA 后在工作线程编码 |
| 本地 PNG/JPEG | 同上，`image` crate 编码 + 原子写 |

**性能与内存**（4K 全屏选区）：

| 操作 | 成本 |
|---|---|
| 建 surface + BitBlt 底图 | 一次 33MB 拷贝，约 10–30ms |
| 提交一个形状（包围盒重绘） | < 1ms（典型） |
| 撤销（重放 N 个形状） | 1–5ms + 一次底图 BitBlt |
| 导出 | 一次 memcpy（33MB），PNG 编码另计 |

**不要做的事**：

- ❌ 导出时去截遮罩窗口（会带上压暗、边框、工具栏，且受 DWM 缩放影响）；
- ❌ 预览和导出各写一套绘制代码（必然出现 1px 偏差、字号不一致）；
- ❌ 每次 `WM_MOUSEMOVE` 全量重放所有形状（应该只重绘包围盒 + 脏区）。

#### 7.3.6 预览/导出一致性的 5 个约束

| # | 约束 | 原因 |
|---|---|---|
| 1 | **同一块像素**：预览直接 `BitBlt` `surface`，不重新渲染 | 从根上消除两条渲染路径 |
| 2 | `GdipSetPageUnit(g, UnitPixel)` | 默认单位是"显示单位"，会按 DC 的 DPI 解释字号/线宽；窗口 DC 与 DIB DC 的 DPI 可能不同 |
| 3 | 笔宽/字号都用像素：`GdipCreatePen1(color, width, UnitPixel, …)`、`GdipCreateFont(family, emsize_px, 0, UnitPixel, …)` | 与第 2 条配套，保证两端数值一致 |
| 4 | 两端都开 `SmoothingModeAntiAlias`，且 1:1 物理像素、不做缩放 | 缩放会让抗锯齿采样网格不同，边缘出现细微差异 |
| 5 | 文字只栅格化一次（提交时写进 surface） | 避免预览用一套字体度量、导出用另一套 |

**常见坑**：

| 坑 | 说明 |
|---|---|
| GDI+ 颜色格式 | GDI+ 是 `0xAARRGGBB`，GDI 的 `COLORREF` 是 `0x00BBGGRR`，混用必出色差 |
| 忘记 `GdipFlush` | 读像素/做马赛克前不 flush，可能读到半成品 |
| GDI+ 对象泄漏 | `GpGraphics`/`GpPen`/`GpFont` 不释放，退出时 `GdiplusShutdown` 会卡住 |
| DIB 行序 | 导出 DIB 自顶向下（负 `biHeight`），CF_DIB 自底向上，两个方向别搞反 |
| 撤销后残留 | 撤销必须从底图重放，不能只"擦掉一个形状" |
| 选区移动语义 | 形状坐标相对选区，拖动选区时标注跟着走（符合直觉）；缩放选区需要 `rebuild` 并保持文档坐标（不缩放形状） |
| GDI+ 首次调用慢 | 启动时预热一次（画个 1×1），避免第一次截图卡顿 |

**验证方式**：

1. 加 debug 开关，把 `surface` 单独 dump 成 PNG，与 `export()` 输出逐像素比较，必须完全相等；
2. 形状黄金图测试：固定尺寸 DIB → 渲染 → 与仓库内 golden 图比对（允许极小阈值）；
3. 把"预览截图"（遮罩窗口客户区）与 `export()` 在选区范围内比对，验证 BitBlt 路径无偏移。

### 7.4 输出层

#### 7.4.1 剪贴板

| 格式 | 用途 | 结构 |
|---|---|---|
| `CF_DIB` | 兼容性最好（微信/QQ/Office/画图） | `BITMAPINFOHEADER`(40B) + **自底向上** BGRA |
| `CF_DIBV5` | 需要 alpha 时（贴图/透明窗口） | 含 `BITMAPV5HEADER` + 掩码 |
| 注册格式 `"PNG"` | 保留无损/透明，部分应用优先 | PNG 字节流 |

时序：

```
OpenClipboard(hwnd)  // 可能被其他程序占用 → 重试 3 次，间隔 10ms
EmptyClipboard
SetClipboardData(CF_DIB, hglobal)   // 系统接管内存，不能 Free
（可选）SetClipboardData("PNG", hglobal_png)
CloseClipboard
```

注意：

- `SetClipboardData` 成功后，`HGLOBAL` 所有权归系统；失败要自己 `GlobalFree`；
- 设置 PNG 需要编码（100–300ms），**默认只放 CF_DIB**，PNG 作为可选项；
- 剪贴板内容在进程退出后仍由系统持有（立即渲染模式），可安全退出。

#### 7.4.2 保存

- 目录：`%USERPROFILE%\Pictures\Screenshots`（可配置）；
- 命名：`Screen_20261020_224715.png`（可配置模板）；
- 原子写：先写 `.tmp` 再 `rename`，避免半截文件；
- 格式：PNG 默认；JPEG 质量 90；WebP 视依赖情况（`image` 的 WebP 编码支持需确认，暂不承诺）；
- 保存线程完成后 `PostMessage(WM_APP_SAVED, path_ptr)` 回主线程弹提示；
- 失败：保留原图在内存，提示用户"另存为"。

#### 7.4.3 贴图窗口

- 独立 `WS_POPUP | WS_EX_TOPMOST | WS_EX_TOOLWINDOW` 窗口；
- 内容：导出后的 `Bitmap`（按 1:1 或缩放绘制）；
- 交互：拖动移动、滚轮缩放、`Esc` 关闭、右键菜单（复制/保存/关闭）、`Ctrl+C`；
- 多张贴图：每张一个窗口，进程退出时统一销毁；
- 视觉：1px 边框 + 阴影（窗口类样式 `CS_DROPSHADOW`，或自绘；不要用 `DwmExtendFrameIntoClientArea` 硬凑）。

### 7.5 系统集成

#### 7.5.1 全局热键

- `RegisterHotKey(hwnd, id, MOD_CONTROL | MOD_ALT | MOD_NOREPEAT, VK_A)`；
- `WM_HOTKEY` 在隐藏窗口的消息循环里处理；
- 冲突（`ERROR_HOTKEY_ALREADY_REGISTERED`，1409）：提示并引导修改配置；
- **PrintScreen 不可靠**：常被系统/厂商工具占用，`RegisterHotKey` 可能失败；如需支持，用 `WH_KEYBOARD_LL` 低层钩子兜底（注意杀软误报与合规）；
- 默认建议 `Ctrl+Alt+A`（用户习惯）或 `Ctrl+Shift+A`（冲突少），可配置。

#### 7.5.2 托盘

```rust
NOTIFYICONDATAW {
    cbSize, hWnd, uID: 1,
    uFlags: NIF_MESSAGE | NIF_ICON | NIF_TIP,
    uCallbackMessage: WM_APP_TRAY,
    hIcon: load_icon(),
    szTip: "window-cap",
}
Shell_NotifyIconW(NIM_ADD, &nid);
nid.uVersion = NOTIFYICON_VERSION_4;
Shell_NotifyIconW(NIM_SETVERSION, &nid);
```

- 回调消息里 `lParam` 携带事件（v4 下低 16 位是鼠标消息），`wParam` 携带坐标；
- 右键 `CreatePopupMenu` + `TrackPopupMenu`（需要先 `SetForegroundWindow` 才能正常消失），结束后 `PostMessage(WM_NULL)`；
- 左键单击 = 立即截图；
- 菜单项：截图、延迟截图、设置、开机自启、退出；
- 图标用 `winresource` 嵌入 `.ico`，运行时 `LoadImageW` 加载；加载失败回退 `IDI_APPLICATION`。

#### 7.5.3 单实例

- `CreateMutexW(None, false, "Local\\window-cap-singleton")`；
- `ERROR_ALREADY_EXISTS` → `FindWindowW(class)` → `PostMessage(WM_APP_ACTIVATE)` → 退出；
- 支持把命令行参数转发给已运行实例（`WM_COPYDATA`）。

#### 7.5.4 开机自启

- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写 exe 绝对路径（带引号）；
- 用 `Win32_System_Registry` 原生 API，或 `windows-registry` crate；
- 托盘菜单里可开关，删除键值即关闭。

#### 7.5.5 配置

```toml
[hotkey]
capture = "Ctrl+Alt+A"
window_capture = "Ctrl+Alt+W"

[capture]
backend = "auto"        # auto | gdi | wgc
include_cursor = false

[output]
save_dir = "%USERPROFILE%/Pictures/Screenshots"
filename = "Screen_{yyyy}{MM}{dd}_{HH}{mm}{ss}"
copy_to_clipboard = true
format = "png"

[ui]
theme = "dark"
language = "zh-CN"
toolbar_position = "auto"
```

- 路径：`%APPDATA%\window-cap\config.toml`；
- 首次运行生成默认配置；
- 解析失败不崩溃：打印错误、用默认值、备份坏文件；
- 配置变更：托盘菜单里"重新加载"（V1 不做实时热重载）。

#### 7.5.6 通知

| 方式 | 优点 | 缺点 |
|---|---|---|
| 托盘气泡（`NIF_INFO`） | 无需注册、零依赖 | 样式老、可能被系统通知设置拦截 |
| Toast（WinRT） | 现代 | 未打包 exe 需要 AUMID/快捷方式，麻烦 |

V1 用托盘气泡；V2 再考虑 Toast。

### 7.6 日志、崩溃与性能

- 日志：`%LOCALAPPDATA%\window-cap\logs` 下 `app.log`（全量）、`app-warn.log`（warn+）、`app-error.log`（error），按天归档，保留 3 天；
- 级别：release 默认 `info`，`--verbose` 打开 `debug`；release 无控制台，debug 构建同时输出 stderr；
- 记录：版本、OS build、DPI、显示器布局、后端选择、耗时、错误码（**不记录图像内容**）；
- panic hook：写崩溃日志 + 尽量恢复系统状态（注销热键、删除托盘图标）；
- 性能埋点：`capture_ms`、`first_paint_ms`、`export_ms`、`save_ms`，debug 日志输出。

## 11. 架构决策记录（ADR）

### ADR-001：采集默认用 GDI，而不是 WGC

- **背景**：WGC 能力更强（独占全屏、HDR、窗口），但默认有黄框，未打包 exe 无法关闭。
- **决策**：区域/全屏用 GDI；窗口用 PrintWindow；WGC 作为可选兜底。
- **代价**：独占全屏/HDR 场景体验不完美。
- **复审条件**：改用 MSIX 分发并获批 `graphicsCaptureWithoutBorder` 能力时。

### ADR-002：遮罩层用原生 Win32，而不是 egui

- **背景**：egui 能显著降低 UI 工作量，但引入 GPU 依赖与混合 DPI 适配成本。
- **决策**：原生 Win32 + GDI/GDI+；文本输入用 EDIT 子窗口。
- **代价**：工具栏/悬停/主题需要自绘。
- **复审条件**：UI 迭代成为瓶颈，或需要复杂设置面板/图库时，可局部引入 egui。

### ADR-003：标注用 GDI+，而不是 Direct2D/tiny-skia

- **背景**：GDI+ 系统自带、CJK 文本好；D2D 质量更好但依赖 D3D；tiny-skia 纯 Rust 但需自接文字排版。
- **决策**：GDI+。
- **代价**：性能不如 D2D，极端大图重绘略慢。
- **复审条件**：出现明显掉帧或需要模糊/滤镜效果时，评估 D2D。

### ADR-004：剪贴板只放 CF_DIB + 可选 PNG

- **背景**：CF_DIB 兼容性最好；PNG 需要编码时间；CF_DIBV5 的 alpha 兼容性差。
- **决策**：默认 CF_DIB；透明/无损需求时追加注册格式 `"PNG"`；CF_DIBV5 暂不做。
- **代价**：透明贴图复制到部分应用会丢 alpha。
- **复审条件**：透明窗口截图/贴图成为常用功能时。

### ADR-005：不引入截图库（xcap/windows-capture）

- **背景**：它们只提供帧，不提供交互；且封装会限制回退与坐标控制。
- **决策**：自研采集层。
- **代价**：多写约 300–500 行平台代码。
- **复审条件**：需要跨平台时，可把 `CaptureBackend` 的 Windows 实现替换为其封装。

### ADR-006：标注与导出共用"成品表面"

- **背景**：常见做法是"预览画一遍、导出再画一遍"，容易出现 1px 偏差、字号不一致、马赛克预览与导出不同。
- **决策**：选区确定时创建一块选区大小的 DIB（`Document::surface`），底图和已提交标注都直接渲染进去；预览整块 BitBlt，导出直接读像素。矢量模型 `shapes` 只用于撤销/重做与重建。
- **代价**：多占一块选区大小的内存（≤ 一屏）；撤销需要全量重放（毫秒级）。
- **复审条件**：需要非破坏性编辑（随时改已画形状）时，仍是同一套 surface + 重放模型，不需要改架构。

## 附录 A：windows-rs 生态与 feature 速查（0.62）

### A.1 feature 机制

`windows` crate 的 feature 不是手写的，而是由 Windows 元数据按命名空间生成的：**0.62.2 共 677 个 feature**，绝大多数对应一个 Win32 模块或一个 WinRT 命名空间；另有少量特殊 feature（`std`、`implement`、`deprecated` 等）。

规则：

- Win32：`Win32_<模块>[_<子模块>]`，如 `Win32_UI_Shell`、`Win32_Graphics_Gdi`；
- WinRT：**不带 `Windows_` 前缀**，如 `Graphics_Capture`、`Media_Ocr`、`UI_Shell`（注意 `UI_Shell` 是 WinRT 的 `Windows.UI.Shell`，与 `Win32_UI_Shell` 是两个 feature）；
- 父 feature 自动带上子 feature（`Graphics_Capture = ["Graphics"]`，`Graphics = ["Foundation"]`）；
- 存在聚合 feature：`Win32`、`Win32_UI`、`Win32_Graphics`、`Graphics` 等——**不要开**，会把编译时间和体积顶满；
- 本文 Cargo.toml 里的 15 个 feature 是"只开需要"的精简列表，已逐项在本机 0.62.2 上验证存在。

查 feature 的三种方式：

1. `cargo add windows --features ...` 的报错/补全会列出候选；
2. docs.rs 对应版本的 Feature flags 页面；
3. 本地 `~/.cargo/registry/src/.../windows-0.62.2/Cargo.toml` 的 `[features]` 段（最准）。

|---|---|
| `Win32_Foundation` | `HWND`/`RECT`/`POINT`/`HANDLE` 等基础类型 |

| `Win32_Graphics_Dwm` | `DwmGetWindowAttribute`、`DWMWA_TRANSITIONS_FORCEDISABLED` |
| `Win32_UI_WindowsAndMessaging` | 窗口/消息/托盘回调 |
| `Win32_UI_Input_KeyboardAndMouse` | `RegisterHotKey`、`SetCapture`、`VK_*` |
| `Win32_UI_Shell` | `Shell_NotifyIconW` |
| `Win32_UI_HiDpi` | `SetProcessDpiAwarenessContext`、`GetDpiForWindow` |
| `Win32_Storage_Xps` | **`PrintWindow`**（位置怪癖） |

可选 `wgc` feature 追加：`Graphics_Capture`、`Win32_System_WinRT`、`Win32_System_WinRT_Graphics_Capture`、`Win32_System_WinRT_Direct3D11`、`Win32_Graphics_Direct3D11`、`Win32_Graphics_Dxgi`、`Win32_Graphics_Direct3D`。

### A.3 同一仓库里的其它 crate（不是 `windows` 的 feature）

`crates/libs/` 下有二十多个独立 crate，分三类：

**1) 基础设施（多为 `windows` 的传递依赖，无需手动添加）**

| crate | 作用 |
|---|---|
| `windows-core` | COM/WinRT 基础类型、`Result`、`Interface`、`Type` |
| `windows-result` / `windows-strings` / `windows-link` / `windows-targets` | 错误码、字符串、链接、导入库 |
| `windows-collections` / `windows-future` / `windows-numerics` / `windows-time` / `windows-threading` | 集合、异步、数值、时间、线程 |
| `windows-implement` / `windows-interface` | COM 宏支持 |
| `windows-registry` | 安全注册表封装（可用于开机自启） |

**2) 绑定生成工具链**

`windows-bindgen`、`windows-metadata`，以及裸 FFI 版本 `windows-sys`（无 `Result` 包装、无 COM 便利）。

**3) 高层 UI/图形库（0.100 预览线，独立版本号）**

| crate | 版本 | 定位 | 对本项目 |
|---|---|---|---|
| `windows-canvas` | 0.100 | 封装 Direct2D/D3D11/DXGI/DirectWrite/WIC 的 2D 绘图库，含离屏 `RenderTarget` + CPU 回读、`TextLayout`、路径/渐变/特效 | **V2 备选**：可替代 GDI+；但 GPU 依赖、预览版、类型与 0.62 不互通 |
| `windows-composition` | 0.100 | 保留模式合成引擎（Visual/SpriteVisual/CompositionDrawingSurface/DesktopWindowTarget） | 不需要：遮罩是 GDI 自绘，引入合成层只会更重 |
| `windows-reactor` | 0.100 | 声明式 WinUI 3（Component/View） | 不适用：依赖 Windows App SDK（即使自包含部署也要带一堆 DLL），与单 exe 目标冲突 |
| `windows-window` / `windows-pickers` / `windows-webview` | 0.100 | 窗口、文件选择器、WebView2 封装 | 不需要 |

**版本耦合提醒**：0.100 系列依赖 `windows-core ^0.100`，而 `windows 0.62` 用的是 `windows-core 0.62`，是两套类型体系。Cargo 允许并存，但 `IUnknown`/`Result`/`GUID` 不能直接互转，跨 crate 需要裸指针桥接。**V1 不引入任何 0.100 系 crate。**

### A.4 其它版本要点

- 句柄是 newtype（`HDC(*mut c_void)`、`HWND(*mut c_void)`），与 C 的裸指针不同，跨类型需 `.0` 转换；
- 大量 API 返回 `Result<()>`/`Result<HANDLE>`，错误用 `?` 传播；
- WinRT 命名空间 feature 的命名在不同版本间有调整（有的旧版本带 `Windows_` 前缀），升级时以实际 `Cargo.toml` 为准；
- `PrintWindow` 在 `Win32::Storage::Xps`（feature `Win32_Storage_Xps`）；
- `GetUpdateRect` 在 `Win32::Graphics::Gdi`；
- 首次编译 `windows` crate 较慢（约 1–2 分钟，视 feature 数量），增量编译正常；
- 同一二进制内不要混用多个 `windows` 主版本；选依赖时注意 `xcap`/`windows-capture` 是否引入不同版本。
