## P4 性能优化（大选区拖动）

用户反馈：拖动大选区时明显卡顿，越大越卡。定位到每个 `WM_MOUSEMOVE` 都调用 `Document::recrop` 重新裁剪整块选区（crop 分配 + 两次整块复制），面积越大越慢。

修复：

- 拖动 / 缩放期间不再重建文档；合成时直接从冻结帧把选区亮区拷进合成缓冲（`copy_frame_region`，逐行 memcpy，无分配）；
- 文档只在鼠标松开后创建一次；
- 每个鼠标事件立即重绘（不再节流）。

中间试过 `SetTimer(8ms)` 合并重绘，但 Windows 默认定时器精度约 15.6ms，实测帧率被压到 ~60fps（100 次移动只绘制 71–89 帧），用户反馈“帧数低”，已移除，改为事件驱动立即重绘（100 次移动绘制 106 帧）。

实测（2250×1200 选区）：

| 版本 | 结果 |
|---|---|
| 优化前 | 100 次强制移动处理 616 ms |
| 去掉每帧重裁剪 | 100 次移动 370 ms（3.7 ms/次），≈1 次绘制/事件 |
| 加 8ms 节流 | 71–89 帧/100 次移动（~60fps，已移除） |
| 当前 | 106 帧/100 次移动，单帧 3.3–3.9 ms（1440p） |

真实“移动选区 + 画箭头 + 确认”E2E 正常，输出 600×400 含箭头。

## P5 修复记录（K6 文字输入框背景）

问题：文字工具弹出一个深色不透明输入框，和屏幕内容割裂。

尝试过“分层子窗口 + 品红颜色键透明”，背景确实透明了，但 ClearType 会在文字边缘留下品红/紫色描边，放弃。

最终方案：子类化 `EDIT`，在 `WM_ERASEBKGND` 里直接把遮罩合成缓冲中该位置的像素 `BitBlt` 到编辑框；`WM_CTLCOLOREDIT` 返回 `NULL_BRUSH` + 透明背景模式，让系统 EDIT 只画文字。既保留原生输入/中文 IME，又做到视觉透明。

验证：

- 打开输入框前后截图对比，编辑框区域（320×65）仅 31 个像素变化（0.15%，为光标），背景逐像素一致；
- 输入「测试 Text 123」时编辑框内 931 个红色文字像素，提交后导出图 889 个；
- 长文本粘贴/滚动无背景残影。

## P5 修复记录（K7 长文本输入）

问题：输入较长文字后，继续输入会把编辑框里已有的文字“擦掉”，只有回车提交后才全部显示；导出时长文本只有一行。

修复：

- `WM_ERASEBKGND` 改用 `GetClipBox`，只重绘失效区域，不再整块覆盖已有文字；
- 输入框高度从 1 行加高到 3 行，换行实时可见；
- `ShapeKind::Text` 增加 `max_width`，导出时按输入框宽度自动换行（仍支持 Shift+Enter 手动换行）。

验证：

- 连续粘贴两段长文本：第二次粘贴后，第一段的三行文字仍然保留（红色像素 4694 → 4887，行带不变）；
- 输入框下方背景区域与打开前逐像素一致（0/9600 差异）；
- 长文本提交后导出为 6 行自动换行排版。
