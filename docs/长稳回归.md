# 长稳回归

> 用途：发布前在目标机上跑一轮长时间稳定性回归，覆盖 24 h 常驻、连续采集、异常恢复与人工主流程。
> 适用版本：v0.10.1 及以后（崩溃诊断、`scripts/soak-24h.ps1` 均在此版本引入）。

## 通过标准

| 项 | 标准 |
|---|---|
| 连续采集 | `--soak 200` 无失败；GDI/USER 句柄增量 ≤ +20；内存增量 ≤ +32 MB |
| 常驻挂机 | 24 h 内进程不退出；周期采集全部成功 |
| 采集耗时 | 单次 ≤ 2000 ms（8 MP 级别应在 150 ms 内） |
| 常驻内存 | ≤ 400 MB，且相对首次采样增长 ≤ 50 MB |
| 异常恢复 | 强制结束后重启，`app-error.log` 出现“上次运行未正常退出”；重启后功能正常 |
| 退出清理 | 正常退出后无 `window-cap` 残留进程；`%LOCALAPPDATA%\window-cap\logs\session.flag` 被删除 |

## 一、自动项（一条命令）

在仓库根目录执行（需先 `cargo build --release`）：

```powershell
# 完整 24 小时
.\scripts\soak-24h.ps1

# 先跑短版确认脚本可用（约 2 分钟）
.\scripts\soak-24h.ps1 -Hours 0.02 -IntervalMinutes 1 -CaptureCount 20
```

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Hours` | 24 | 常驻时长（小时，可小数） |
| `-IntervalMinutes` | 15 | 周期采集间隔（分钟） |
| `-CaptureCount` | 200 | 连拍次数 |
| `-Force` | 关 | 自动结束已存在的 `window-cap` 进程 |

输出（`%LOCALAPPDATA%\window-cap\logs`）：

- `soak-<时间戳>.csv`：每次周期采集的耗时、内存、GDI、USER、句柄数
- `soak-<时间戳>-summary.txt`：结论 `PASS` / `FAIL` 与失败原因
- 脚本退出码：0 通过，1 失败

> 说明：脚本的周期采集由独立进程完成，常驻实例只验证“长时间存活 + 空闲内存稳定”；常驻实例在真实交互下的内存/句柄，请结合下面的人工项观察。

## 二、人工项（约 30 分钟，穿插在挂机期间）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 连续截图 20 次（含标注、文字、贴图） | 无崩溃；工具栏/提示正常；第 20 次与第 1 次手感一致 |
| 2 | 同时贴 10 张图，再逐张保存/复制/关闭 | 内存回落，无句柄泄漏 |
| 3 | 托盘菜单逐项点一遍（设置/重载配置/自启开关/退出） | 无异常；设置页保存后热键仍生效 |
| 4 | 用别的程序占用 `Ctrl+Alt+A` 后启动 | 有明确提示，不静默失败 |
| 5 | 热键唤起遮罩 → 取消 ×5 | 每次都能正常退出遮罩，无残留窗口 |
| 6 | 任务管理器强制结束进程 → 重新启动 | 日志出现“上次运行未正常退出”，功能正常 |
| 7 | 正常退出（`Ctrl+Alt+Q` / 托盘退出） | 无残留进程，`session.flag` 已删除 |
| 8 | 双屏/混合 DPI（如有） | 工具栏归属屏正确、跨屏拖动尺寸稳定、提示标签落在鼠标所在屏 |

## 三、记录与回传

完成后把以下内容存档（可直接作为发布说明的依据）：

1. `soak-<时间戳>-summary.txt` 与 CSV
2. `app.log` / `app-warn.log` / `app-error.log` 中当天的文件
3. 人工项结果（见下方模板）

```text
日期 / 机器：
系统版本 / DPI / 显示器布局：
自动项结论：PASS / FAIL（失败项：）
人工项：1 通过 / 2 通过 / …（异常项写现象 + 日志时间点）
备注：
```

## 四、常见问题

- **脚本报“检测到 N 个 window-cap 进程”**：确认没有正在进行的手工截图，然后加 `-Force` 重跑。
- **常驻实例在挂机期间退出**：先看 `app-error.log` 与 `last-crash.txt`；若为 force kill 造成，脚本会自动清理 `session.flag`。
- **热键失效**：多半是别的程序占用了 `Ctrl+Alt+A`，换一个热键或用设置页重新录制。
- **内存持续上涨**：CSV 中 `memory_mb` 单调上升即可判定；对照 `--soak` 结果区分“常驻泄漏”还是“采集分配器保留”。
